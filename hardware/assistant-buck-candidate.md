# TPS62133 separated-island placement candidate

Status: **PLACEMENT CANDIDATE ONLY — NOT REVIEWED — NOT FOR PRODUCTION**

## Purpose

The prior full-board and local routing attempts coupled the battery-protection geometry too tightly to the TPS62133 cell. The new candidate tests a different physical architecture without changing any electrical topology or component package:

* J4/F1/D3/Q1/R1/R2 remain the battery-input/protection block;
* U1/C1/C2/C3/C4/L1 move as a separate regulator island into free central board area;
* Q1 Source -> C1 is treated as an upstream low-impedance `BUCK_IN` feed, not as the local TPS62133 high-di/dt loop;
* package-size reduction is deferred until a current-package candidate is proven impossible with realistic local/common ground copper.

The active PCB is intentionally **not** overwritten. The candidate file is:

`hardware/esp32-e220-assistant-buck-candidate.kicad_pcb`

It is reproducibly generated by:

`python3 hardware/make_assistant_buck_candidate.py`

The helper removes all top-level segments, vias and zones from the output before moving the six buck-cell footprints. This prevents rejected experimental copper from becoming accidental evidence.

The intent is deliberately different from the rejected legacy cell: C1 and C3 have their power pads exposed toward their respective feed/output corridors, while their GND pads sit toward the local PGND side. C2 and C4 are positioned so their signal/power pads have short direct corridors; their GND pads should be able to drop immediately into the common ground structure.

## Ground and thermal proof policy

Primary reference: Texas Instruments TPS6213x datasheet, SLVSAG7F Rev.F, section 11, especially the layout guidelines and recommended layout example.

The next retained `hardware/evidence/` feasibility proof must not repeat the earlier artificial constraint that every capacitor GND pad requires a long individual F.Cu route to EP. The intended two-layer proof is:

* compact local F.Cu GND copper around AGND/PGND/EP where geometry permits;
* direct AGND/PGND/EP common connection;
* immediate purposeful GND vias from local capacitor-return copper into a continuous B.Cu ground plane;
* no ground copper intruding into the SW high-dv/dt area;
* no filled/capped via-in-pad assumption;
* VOS kept as a separate short sense trace to C3 VOUT, not merged into a power-style `5V_SYS` route.

The planner must inspect actual zone fill and return paths. A ground zone is allowed for the temporary proof because the common ground plane is part of the intended electrical implementation; it must not be used to conceal an impossible route or a clearance problem.

## Required validation gate

This environment did not provide `kicad-cli` or the KiCad `pcbnew` Python module, so no claim of native DRC/ERC or routing feasibility is made here.

Before adopting this placement into `hardware/esp32-e220.kicad_pcb`:

1. Run the project schematic/PCB parity check on the candidate:
   `python3 hardware/check_schematic_pcb_sync.py --pcb hardware/esp32-e220-assistant-buck-candidate.kicad_pcb --output hardware/evidence/buck-and-5v-checkpoints-2026-08-18/assistant-buck-sync.json`.
2. Run native KiCad PCB DRC and classify out-of-scope unconnected items separately from geometry findings.
3. Invoke `pcb_routing_planner` on a retained `hardware/evidence/` copy and create real temporary copper for the bounded TPS62133 cell, including the local/common ground implementation and thermal-via concept.
4. Require a temporary proof with no real shorts/clearance/hole/courtyard errors and no mandatory in-scope unconnected pin.
5. Require function-aware checks for the C1 input loop, SW/L1, C3 output loop, VOS Kelvin sense, SS/TR/C4, FSW/FB/DEF/EN, AGND/PGND/EP and thermal path.
6. Invoke `pcb_reviewer` independently.
7. Only after `ROUTING PLAN READY` plus reviewer PASS may `pcb_layout_dfm` adopt the candidate into the active PCB and implement routing transactionally.

If this current-package candidate fails after a realistic ground-plane proof, then escalate to `PACKAGE SIZE REVIEW REQUIRED`; do not shrink components merely to preserve the old coordinates.

## Static validation performed in this review environment

The candidate was parsed as a KiCad S-expression after generation. The static checks found:

* 33 footprints in active PCB and 33 footprints in candidate;
* only U1/C1/C2/C3/C4/L1 footprint placement/orientation changed;
* no changes to footprint identity, value, pad number, pad net, pad size or pad shape;
* 0 top-level segments, 0 vias and 0 zones in the candidate;
* no positive-area overlap between the project footprint `F.CrtYd` bounding boxes.

These checks detect accidental text/generator drift but do not evaluate KiCad design rules, mask clearances, copper fill, electrical loop quality or manufacturability. Native KiCad and the project agents remain the acceptance gate.
